## ast.Assign, ast.AugAssign
	action
	Декілька послідовних нерозгалужених операторів примусово групуються ("orphan trimming") в єдиний "basic block", розділений \n. Розміщується вздовж вертикальної осі.
	ast.If (з orelse)
	question
	Атрибут test стає текстом умови. Вузли гілки body підключаються через покажчик one (рух вниз по шампуру). Вузли гілки orelse підключаються через покажчик two (рух строго горизонтально вправо).
	ast.If (без else)
	question
	Покажчик two (no) спрямовується на порожній вузол-заглушку action (з текстом pass), після чого обидві гілки сходяться в точці Common Fate Merge на головному шампурі.
	ast.If (elif chain)
	вкладені question
	Оскільки Python формує elif як вкладений ast.If всередині попереднього orelse, це ініціює каскадну серію вузлів question, що розширюється горизонтально вправо.

## ast.For, ast.While
	loop_start, loop_end
	Розміщуються на вертикальній осі, формуючи межі ітерації. loop_end закриває тіло циклу, генеруючи зворотний покажчик на відповідний loop_start.
	ast.Return
	action → end
	Термінальна дія. Генерує вузол action з текстом повернення. Покажчик next (one) діє як абсолютний goto, завжди спрямовуючись на єдиний глобальний термінал end.
	ast.Raise
	action → end
	Виняток перериває нормальний потік. Скеровується до спільного end або обробляється локальним ast.ExceptHandler на правій периферії.
	ast.Try (body)
	action (Wrapper)
	Початок зони ризику. Вузол індикує вхід у небезпечний блок, потік виконання продовжується вниз по шампуру.
	ast.Try (except)
	синтетичний question
	Відразу після зони ризику впорскується невидима в коді умова ("Exception caught?"). Покажчик yes веде вправо до блоків ExceptHandler. Покажчик no йде вниз.

## Обробка специфічних Python патернів
   * Try / Except / Finally: Втілює евристику Rightward Degradation. Зона ризику розміщується на центральній осі. Блоки обробки винятків (ExceptHandler) примусово виштовхуються праворуч. Блок finally (finalbody) виконує функцію абсолютної точки конвергенції (Common Fate Merge point), куди сходяться всі покажчики one перед подальшим виконанням алгоритму.
   * For / Else та While / Else: У Python блок else для циклу виконується лише за умови природного завершення ітерацій (без break). Топологічно блок else розміщується безпосередньо після макроікони loop_end на основному шляху. Вузол ast.Break обробляється як action, чий покажчик next повністю обходить як loop_end, так і блок else, перестрибуючи до коду, що слідує за конструкцією циклу.
   * Спискові включення (List Comprehensions): Структури ast.ListComp містять високу щільність логіки. Заборонено "вибухати" (explode) їх на складні ланцюги loop_start та question, оскільки це руйнує візуальну простоту. Вони мапляться на єдиний вузол action, що містить вихідний текст включення.
   * Вкладені функції (Nested Defs) та Lambda: Хоча лямбда-функції та вкладені визначення діють у єдиному лексичному контексті батьківської функції, для DRAKON вони є окремими межами виконання. Вони виділяються у незалежні під-діаграми і викликаються з батьківського потоку через макроіконку insertion.
