# Метрики алгоритмічної складності: SIS та RDC

Інтелектуальна платформа HTSE використовує спеціалізовані кількісні метрики для оцінки когнітивної складності згенерованого DRAKON IR. Якщо метрики виходять за межі нормативів, агент отримує сигнал про необхідність архітектурного рефакторингу діаграми.
   * Skewer Integrity Score (SIS - Індекс цілісності шампура): Метрика, що розраховує концентрацію бізнес-логіки на головній осі виконання. Розрахунок: Це відношення кількості вузлів, що лежать виключно на головному вертикальному шляху (від header до end за допомогою послідовних покажчиків one), до загальної кількості вузлів алгоритму. Норматив: Ідеальна діаграма має   . Якщо показник падає нижче   , алгоритм визнається надмірно фрагментованим (перевантаженим умовними переходами). Це є жорстким сигналом для агента про необхідність розбиття Примітива на паралельні гілки Силуету.
   * Rightward Degradation Count (RDC - Глибина деградації вправо): Метрика, що вимірює максимальну просторову глибину горизонтальної вкладеності. Розрахунок: Обчислюється шляхом відстеження найдовшого безперервного ланцюга переходів, що використовують покажчик two (відхилення вправо). Норматив: Максимально допустиме значення    (в окремих випадках до 4). Якщо   , когнітивне навантаження на інженера стає критичним. LLM-агент зобов'язаний вилучити ці глибокі каскади умов у зовнішні підпрограми (через ікону insertion).

## Валідатор графа (Graph Validator) та автоматичні виправлення
Завдання задоволення обмежень (Constraint Satisfaction Problem) реалізується через незалежний детермінований мікросервіс Graph Validator, який проганяє згенерований LLM JSON IR через конвеєр автоматичних перевірок та виправлень (Autofix) перед рендерингом.
      1. Немає b0 (Header) або множинні End (Порушення Single Terminal Constraint):
      * Помилка: Алгоритм не може мати множинних точок виходу. Усі переривання (return) повинні сходитися.
      * Autofix: Валідатор виявляє всі вузли, що не мають поля one (тупикові вузли). Він генерує один спільний вузол type: "end". Всі попередні тупики трансформуються у вузли action, а їхні порожні покажчики one переписуються на ідентифікатор створеного термінала.
      2. Лівобічні вектори (Question без Two):
      * Помилка: Умовні розгалуження не мають права скеровувати потік ліворуч, руйнуючи векторну геометрію.
      * Autofix: Будь-які спроби створити нестандартні напрямки відхиляються. Якщо вузол question не містить покажчика two, валідатор повертає JSON-RPC помилку до LLM для ітеративної регенерації, вимагаючи вказати альтернативний шлях.
      3. Недосяжні вузли (Orphans / Dangling Pointers):
      * Помилка: Вказівники посилаються на ідентифікатори, відсутні в словнику items, або існують вузли, до яких не веде жоден шлях.
      * Autofix: Запускається обхід графа в глибину (Depth-First Search, DFS) від стартового вузла. Всі невідвідані вузли маркуються як мертвий код і видаляються (Orphan Trimming). Для посилань на неіснуючі ID генерується порожній action з текстом /* Auto-generated stub */ для уникнення падіння рушія.
      4. Anti-Twin Error (Помилка близнюків у Силуетах):
      * Помилка: Паралельні гілки Силуету не можуть з'єднуватися між собою прямими горизонтальними лініями (стрибки в середину іншої логіки заборонені).
      * Autofix/Review: Прямі зв'язки примусово розриваються. Передача управління дозволена виключно через створення вузла навігації address, що вказує лише на ідентифікатор заголовка (header) цільової гілки.
