# Принцип "правого зміщення" (Rightward Degradation)

Евристика "правого зміщення" (Rightward Degradation) є фундаментальним стовпом когнітивної ергономіки DRAKON. Вона формулюється аксіомою: «Чим правіше, тим гірше» (The further right, the worse). Цей принцип диктує, що будь-які альтернативні маршрути, обробники помилок (catch/except), переривання та малоймовірні крайові випадки (edge cases) повинні бути алгоритмічно витіснені на далеку праву периферію діаграми. Око інженера-архітектора, завдяки такому просторовому ранжируванню, підсвідомо ідентифікує праву зону як зону ризику та виняткових ситуацій, дозволяючи сфокусуватися виключно на лівій вертикальній осі при аналізі бізнес-логіки.

## Автоматичне визначення "Happy Path" з Python-коду
Центральна вертикальна вісь, яка уособлює "сценарій найбільшого успіху", називається "Шампуром" (Skewer). LLM-агент використовує комбінацію структурних евристик для автоматичного розпізнавання Happy Path у сирому дереві AST:
   * Евристика 1 (Векторна перевага): За топологічними обмеженнями, для будь-якої біфуркації (question), покажчик one (напрямок вниз) завжди призначається для продовження Happy Path. Покажчик two (напрямок вправо) резервується для відхилень або обробки помилок.
   * Евристика 2 (Синтетичні пастки винятків): При аналізі try/except, блок body завжди вважається безпечним і залишається на шампурі (вектор one). Згенерована синтетична умова перехоплення винятку спрямовує потік у разі помилки по вектору two (вправо) до обробників.
   * Евристика 3 (Безперервність ланцюга): Happy Path ідентифікується як найдовший безперервний ланцюг виконання логіки, який не обривається операторами ast.Return або ast.Raise.
Семантика гілок question.one та question.two
На відміну від класичних блок-схем, де виходи з умови є візуально рівнозначними, у DRAKON вони мають сувору ієрархію:
   * question.one (YES): Цей покажчик завжди спрямований вертикально вниз. Він уособлює рух по "Шампуру". Логічно він відповідає підтвердженню успішності перевірки (умова виконується, потік продовжується без перешкод).
   * question.two (NO): Цей покажчик завжди спрямований строго горизонтально вправо. Він означає відхилення від ідеального сценарію, обробку помилки або перехід до альтернативного варіанту (наприклад, ланцюга elif).

## Практичні приклади: Мапінг Guard Clauses
Поширений Python-патерн "раннього виходу" (Guard clause) виглядає як: if not valid: return error. З точки зору синтаксичного дерева, істинність умови not valid призводить до виконання тіла body (return error). Однак семантика DRAKON вимагає оцінювати бізнес-намір. Оскільки невалідність даних є відхиленням від успіху, агент застосовує семантичну інверсію. Вузол question (з текстом data is valid?) призначає позитивний сценарій (дані валідні, виконання продовжується) на атрибут one (вниз). Достроковий вихід (return error) примусово відкидається на атрибут two (вправо), стаючи термінальною гілкою, що підкреслює її статус як обробки "гіршого" варіанту. Це гарантує, що основний код функції (після перевірок) залишиться на центральному шампурі, зберігаючи когнітивну ергономіку алгоритму.
