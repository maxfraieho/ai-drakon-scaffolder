# Стандарт форматування документації Garden Bloom

Цей документ визначає єдині стандарти та правила структурування, маркування та взаємозв'язку файлів документації у базі знань AI-DRAKON.

## Шаблон метаданих (Frontmatter)

Кожен `.md` файл у базі знань повинен починатися з обов'язкового блоку YAML frontmatter:

```yaml
---
tags:
  - domain:<concept|architecture|kb|manual|plan|report|agent|ux|meta>
  - status:<canonical|active|draft|archived>
  - format:<spec|guide|reference|plan|report|skill|index>
created: YYYY-MM-DD
updated: YYYY-MM-DD
tier: <1|2|3>
title: "НАЗВА ДОКУМЕНТУ"
lang: uk
---
```

### Доменна таксономія (domain)
- `domain:concept` — бачення, філософія, ключові ідеї.
- `domain:architecture` — архітектурний дизайн системи, технічні рішення.
- `domain:kb` — база знань, специфікація DRAKON IR, промпти.
- `domain:manual` — практичні інструкції, посібники користувача.
- `domain:plan` — плани реалізації, спринти.
- `domain:report` — результати тестів, аудити, каталоги багів.
- `domain:agent` — навички агентів, робочі процеси AGY.
- `domain:ux` — UI/UX аудити, дизайнерські рішення.
- `domain:meta` — стандарти та мета-документація про саму базу знань.

### Рівні важливості (tier)
- `tier: 1` — **canonical** (архітектура, концепція, стандарти, специфікації — не змінюються без процедури Change Request).
- `tier: 2` — **active** (інструкції, KB, плани — живі документи, що оновлюються в процесі розробки).
- `tier: 3` — **reference** (плани реалізації конкретних фіч, згенеровані звіти, результати UX-аудитів).

## Вікі-посилання (Wiki links)

Для взаємних посилань між документами бази знань використовуються подвійні квадратні дужки `[[НАЗВА_ФАЙЛУ]]` без вказання розширення `.md`. Перевага надається оригінальній назві файлу у верхньому регістрі для канонічних документів або точній назві markdown файлу.

Приклади: `[[01-vision]]`, `[[01-drakon-ir-spec]]`, `[[manual-pipeline-a]]`.

### Два типи вузлів графу

| Тип | Файли | Incoming limit |
|-----|-------|---------------|
| **MOC / Index** | `_INDEX.md`, `INDEX.md`, `README.md` | Необмежено — це їх призначення |
| **Leaf / Content** | Всі інші `.md` | Max 5 incoming |

### Контроль вхідних зв'язків (Incoming Link Control)

**Правило Nearest Ancestor:** Посилай завжди на `_INDEX` СВОГО розділу, а не на root `[[INDEX]]`.
- `docs/concept/03-architecture.md` → `[[concept/_INDEX]]` ✅
- `docs/concept/03-architecture.md` → `[[INDEX]]` ❌

**Правило No Content Hubs:** Не перетворюй leaf-ноти на хаби.
Якщо doc X вже досяжний через `_INDEX` за 1 перехід — пряме посилання на X надлишкове.
- `[[concept/_INDEX]]` достатньо, не додавай ще `[[01-vision]]` в ту ж секцію.

**Виняток:** Специфікації та API-документи (`[[01-drakon-ir-spec]]`) можуть бути прямими цілями, якщо поточний doc безпосередньо залежить від них (не просто "пов'язаний з темою").
