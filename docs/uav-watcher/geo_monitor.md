## Призначення
Модуль `geo_monitor` відповідає за динамічне формування списку географічних 
назв (населених пунктів) навколо поточних локацій користувачів. Він 
використовується для створення регулярних виразів, що дозволяють фільтрувати 
або відстежувати повідомлення, пов'язані з конкретними регіонами перебування 
членів сім'ї.

## Архітектура
Модуль реалізує патерн "динамічного гео-контексту". Він поєднує статичні 
ключові слова з даними, отриманими в реальному часі через зовнішній API 
OpenStreetMap (Overpass). Для оптимізації продуктивності та зменшення 
кількості запитів до API використовується дворівнева система кешування: 
локальний словник у пам'яті з прив'язкою до координатних сіток.

## Ключові функції
- `fetch_settlements(lat, lon)` — отримує список населених пунктів у радіусі 
  30 км від заданої точки, використовуючи кеш для уникнення повторних запитів.
- `get_all_active_locations(db_path)` — витягує з бази даних актуальні 
  координати користувачів, що оновили свій статус за останні 8 годин.
- `build_pattern_from_locations(db_path, base_keywords)` — головна функція, 
  що агрегує статичні ключові слова та динамічні назви населених пунктів у 
  єдиний скомпільований регулярний вираз.

## Потік виконання
1. Отримання списку активних координат користувачів з локальної БД.
2. Паралельний запит до Overpass API для кожної унікальної локації (з 
   урахуванням кешування за координатами).
3. Фільтрація та нормалізація назв населених пунктів (вибір української 
   назви або стандартної).
4. Об'єднання базових ключових слів та отриманих гео-назв у єдиний набір.
5. Компіляція набору в регулярний вираз з ігноруванням регістру.

## Залежності
- `sqlite3` — для доступу до локальної бази даних локацій.
- `Overpass API` — зовнішній сервіс для отримання географічних даних.
- `asyncio` — для асинхронного виконання мережевих запитів.
