## Призначення
Модуль `shelter_search` відповідає за виявлення найближчих до користувача 
захисних споруд цивільного захисту на основі географічних координат. 
Він забезпечує інтеграцію з картографічними сервісами для отримання 
актуальних даних та використовує локальні статичні дані як резервний 
механізм (fallback).

## Архітектура
Модуль побудований як сервіс-адаптер, що об'єднує зовнішні API (OpenStreetMap) 
та внутрішню систему кешування. Логіка фільтрації відсікає об'єкти, що не 
є укриттями (наприклад, альтанки чи зупинки), забезпечуючи релевантність 
результатів для безпеки користувачів.

## Ключові функції
- `_haversine(lat1, lon1, lat2, lon2)` — обчислює відстань між двома 
  географічними точками у метрах.
- `_query_overpass(lat, lon, radius_m)` — виконує запит до Overpass API для 
  пошуку об'єктів з тегами цивільного захисту в заданому радіусі.
- `_nominatim_address(lat, lon)` — здійснює зворотне геокодування для 
  отримання адреси (вулиця, номер будинку) за координатами.
- `_city_key_from_coords(lat, lon)` — визначає ідентифікатор міста для 
  вибору відповідного статичного файлу з даними укриттів.

## Потік виконання
1. Отримання запиту з координатами користувача.
2. Спроба отримання даних через Overpass API з фільтрацією за типом об'єкта.
3. Якщо дані отримані, проводиться їх валідація та збагачення адресою через 
   Nominatim.
4. У разі відсутності даних від API або помилки, система звертається до 
   локальних статичних файлів (seed-даних) для пошуку укриттів у відповідному 
   регіоні.
5. Повернення списку знайдених укриттів з відстанню до них.

## Залежності
- `Overpass API` — основне джерело геоданих про інфраструктуру.
- `Nominatim (OpenStreetMap)` — сервіс для перетворення координат у зрозумілу 
  адресу.
- `asyncio` — для асинхронної роботи з мережевими запитами та керування 
  блокуванням кешу.
