## Призначення
Модуль `uav_watcher` відповідає за моніторинг Telegram-каналів у реальному часі
з метою виявлення загроз від БПЛА та ракетних атак. Він виконує первинну
фільтрацію повідомлень, оцінку рівня небезпеки та керує сповіщеннями для
користувачів, мінімізуючи дублювання інформації.

## Архітектура
Модуль побудований на базі клієнта `Telethon` для підключення до Telegram.
Логіка базується на регулярних виразах для класифікації повідомлень (загроза,
відбій, тривога) та евристичних алгоритмах оцінки близькості загрози до
цільового регіону. Стан загроз зберігається у локальному файлі для
забезпечення стійкості до перезапусків.

## Ключові функції
- `score_proximity(text, city_keywords)` — оцінює ступінь загрози за шкалою
  від 1 до 10 на основі згадок ключових слів та близькості до міста.
- `_infer_level(text, reason)` — визначає рівень критичності загрози (1-3)
  на основі контексту повідомлення.
- `_load_threat_state()` / `_save_threat_state()` — керують персистентністю
  стану активної загрози для коректної обробки відбоїв тривоги.
- `load_config()` — зчитує конфігурацію моніторингу з файлу `config.json`.

## Потік виконання
1. Моніторинг вхідних повідомлень через Telegram API.
2. Перевірка тексту повідомлення на відповідність патернам загроз або відбою.
3. Якщо виявлено загрозу: розрахунок близькості та рівня небезпеки.
4. Перевірка часових обмежень (throttling) для запобігання спаму.
5. Відправка сповіщення користувачу та оновлення локального стану загрози.

## Залежності
- `telethon` — для взаємодії з Telegram.
- `httpx` — для мережевих запитів.
- `geo_monitor` — для побудови патернів локацій.
- `dotenv` — для керування конфігураційними змінними середовища.
