# Принципи самобалансування Вікі-графу та оновлення довгострокової пам'яті

Цей документ визначає фундаментальні принципи та стандарти структурування бази знань (Вікі) платформи AI-DRAKON, а також автоматизації довгострокової пам'яті за допомогою інструменту **MemPalace**.

---

## 1. Стандарт самобалансування Вікі-графу (Zettelkasten MOC Tree)

Для запобігання перетворення бази знань на хаотичну "павутину" (cluttered spiderweb) і забезпечення її легкої читаності у вигляді дерева, всі статті та агенти-документознавці керуються такими правилами:

### А. Бюджет зв'язків (Link Budget)
Для кожної кінцевої статті (leaf node) встановлюється суворий ліміт зв'язків:
* **Батьківський зв'язок (Parent MOC Link)**: Строго 1 посилання на локальну карту контенту (`_INDEX.md` або `README.md`) поточного розділу.
* **Послідовний зв'язок (Sequential Sibling Link)**: Максимум 1 посилання на наступний логічний крок (`Read-Next` патерн) для хронологічних або нумерованих розділів (наприклад, `01-...` посилається на `02-...`).
* **Контекстуальні зв'язки (Semantic/Related Links)**: Максимум 1–2 посилання на найбільш семантично пов'язані статті з інших розділів.
* **Результат**: Будь-який листок повинен мати **≤ 3–4 вихідних та вхідних зв'язків**.

### Б. Структура MOC (Map of Content) та викорінення спаму
* Жоден кінцевий листок не повинен посилатися безпосередньо на глобальний індекс `INDEX.md`. Це створює інформаційний спам навколо кореневого вузла.
* Натомість листок посилається на свій локальний індекс розділу (MOC): наприклад, `docs/agents/agy/01-docs-agent/SKILL.md` посилається на `[[agents/_INDEX]]` (MOC розділу `agents`).
* Кореневий `INDEX.md` містить зв'язки лише з основними MOC-файлами першого рівня (`architecture/_INDEX`, `agents/_INDEX`, `kb/_INDEX` тощо).

### В. Чистота шляхів вікі-посилань
* Усі посилання мають бути відносними, чистими й не містити зайвих префіксів типу `docs/` чи суфіксів типу `.md`.
* Формат: `[[kb/_INDEX]]` або `[[agents/agy/01-docs-agent/SKILL]]`.

## 2. Систематичне оновлення довгострокової пам'яті (MemPalace)

Для збереження актуальності знань ШІ-агента та миттєвого пошуку архітектурних рішень без тривалого очікування індексації, впроваджено такі інженерні стандарти:

### А. Фонова індексація за допомогою Git-хука (`post-commit`)
* Вся робота з базою коду та документацією синхронізується з локальним сховищем **MemPalace** автоматично.
* Для цього налаштовано автоматичний хук [.git/hooks/post-commit](file:///data/data/com.termux/files/home/workspace/ai-drakon-scaffolder/.git/hooks/post-commit):
  ```bash
  #!/bin/sh
  nohup mempalace mine /data/data/com.termux/files/home/workspace/ai-drakon-scaffolder --wing ai_drakon_scaffolder > /dev/null 2>&1 &
  ```
* Завдяки запуску через `nohup ... &` індексація відбувається миттєво після створення коміту у фоні, порівнює таймштампи лише змінених файлів і не блокує процес розробки.

### Б. Використання MemPalace для пошуку оптимальних рішень
Перед початком реалізації будь-якої складної задачі ШІ-агент або розробник ЗАВЖДИ повинен зробити швидкий пошук по базі знань:
```bash
mempalace search "ключовий_запит"
```
Це дозволяє відновити контекст попередніх архітектурних рішень, уникнути дублювання коду та використовувати перевірені шаблони.
