# 02 — Мова DRAKON: основи для розробника

## Що таке DRAKON

DRAKON (Дружня Алгоритмічна мова, Яка Забезпечує Наочність) — візуальна алгоритмічна мова, розроблена для програми «Буран» в Інституті прикладної математики АН СРСР. Основна мета — зробити алгоритм одночасно **виконуваним** (транслюється в код) і **когнітивно ергономічним** (читається без пояснень автора).

DRAKON не є черговою нотацією для малювання блок-схем. Це мова з **математично строгими топологічними інваріантами**, що роблять кожну діаграму єдино правильною для даного алгоритму.

---

## Топологічні інваріанти (правила, які не можна порушити)

**1. Шампур (Happy Path Axis)**
Головна вертикальна вісь — «шампур» — завжди по центру. На ній розташований основний (щасливий) шлях виконання: вхід зверху, вихід знизу. Читач дивиться по вертикалі.

**2. Заборона перетинів**
Жодні лінії зв'язку не можуть перетинатися. Якщо алгоритм вимагає перетину — потрібна декомпозиція на Silhouette.

**3. Правостороннє відхилення**
Альтернативні маршрути, обробники помилок, виняткові гілки — завжди праворуч від шампура. Ліворуч — заборонено.

**4. Ортогональна маршрутизація**
Усі лінії — горизонтальні або вертикальні. Діагональні лінії заборонені.

**5. Єдиний термінал**
Кожна діаграма має рівно одну точку входу (START) і одну точку виходу (END).

---

## Два типи діаграм

### Primitive (Примітив)
Базова структура для функцій з цикломатичною складністю CC ≤ 10.

- Одна вертикальна вісь
- Усі розгалуження повертаються на шампур
- Читається зверху вниз без горизонтальних рухів погляду

```
   START
     │
  [дія 1]
     │
  [рішення?]──No──[помилка]
     │                │
    Yes               │
     │                │
  [дія 2]◄────────────┘
     │
    END
```

### Silhouette (Силует)
Макроструктура для складних алгоритмів (CC > 10).

- Алгоритм декомпозується на **гілки (branches)** — паралельні вертикальні смуги
- Кожна гілка має назву (header)
- Гілки виконуються послідовно зліва направо
- Забезпечує двостадійне сприйняття: макроструктура через заголовки, мікроструктура через дії всередині

```
  [гілка 1: Ініціалізація] | [гілка 2: Обробка] | [гілка 3: Завершення]
         START             |       [цикл]        |       [cleanup]
         [init]            |    [process item]   |       [report]
           │               |         │           |          │
          END ─────────────┴─────────┴───────────┴─────────►END
```

## DRAKON IR — формат проміжного представлення

AI-DRAKON використовує JSON-формат IR для зберігання, передачі та рендерингу діаграм. Координати в IR **відсутні** — рендерер обчислює розташування автоматично на основі топологічних правил.

### Структура верхнього рівня

```json
{
  "name": "MyClass.process_data",
  "params": "data: list, timeout: int = 30",
  "items": {
    "1": { "type": "terminator", "text": "START", "next": "2" },
    "2": { "type": "action",     "text": "validate(data)", "next": "3" },
    "3": { "type": "decision",   "text": "valid?", "yes": "4", "no": "5" },
    "4": { "type": "action",     "text": "process(data)", "next": "6" },
    "5": { "type": "action",     "text": "raise ValueError", "next": "6" },
    "6": { "type": "terminator", "text": "END", "next": null }
  }
}
```

### Типи вузлів

| Тип | Призначення | Зв'язки |
|-----|-------------|---------|
| `terminator` | START / END | `next` |
| `action` | Будь-яка дія (виклик, присвоєння) | `next` |
| `decision` | Умовне розгалуження | `yes`, `no` |
| `loop_start` | Початок циклу | `next` |
| `loop_end` | Кінець циклу / умова продовження | `loop` (назад), `next` (вихід) |
| `call` | Виклик підсхеми | `next` |
| `branch` | Заголовок гілки Silhouette | `next` |

## Маппінг Python → DRAKON

| Конструкція Python | Вузол DRAKON | Правило |
|-------------------|--------------|---------|
| `if/elif/else` | `decision` chain | Common Fate Merge: усі гілки повертаються на спільний вузол |
| `for/while` | `loop_start` + `loop_end` | Умова виходу — на `loop_end` |
| `break` | `action` → jump past `loop_end` | Синтетичне ребро |
| `try/except` | `action` + synthetic `decision` | Виняток = правостороннє відхилення |
| `finally` | convergence `action` | Обидва шляхи зустрічаються |
| `with` | collapsed `action` | Контекстний менеджер як атомарна дія |
| Послідовні присвоєння | один `action` | Basic Block grouping |

## Цикломатична складність і вибір типу діаграми

Architect-agent вимірює CC (McCabe Cyclomatic Complexity) перед генерацією:

```
CC 1–10   → Primitive  (швидкий шлях: AST-транслятор без LLM)
CC 11–20  → Silhouette (рівень "silhouette": LLM + YAML-посередник)
CC 21–50  → Silhouette (рівень "branch": глибока декомпозиція)
CC > 50   → Silhouette (рівень "deep": обов'язкова ручна ревізія)
```

Для `primitive` використовується **детермінований AST-транслятор** (`PythonAnalyzer`) — без LLM, без варіативності. Для складніших функцій — LLM із спрощеним YAML як посередником для зменшення галюцинацій.
