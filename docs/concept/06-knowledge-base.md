# 06 — База знань предметної області

## Роль бази знань у системі

AI-DRAKON використовує базу знань (KB) на двох рівнях:

1. **Системні промпти агентів** — `architect-agent` і `drakon-agent` мають вбудовані знання правил DRAKON: топологічні інваріанти, маппінг конструкцій, типи вузлів. Це "frozen knowledge" — оновлюється з кодом агента.

2. **Предметні знання користувача** — нотатки, документи, схеми, що накопичуються через `docs-agent` і редактор Notes. Це "living knowledge" — оновлюється в реальному часі.

### Блок 02: Вузлові патерни
```
02-node-patterns.md

  - Маппінг Python → DRAKON
  - Common Fate Merge (злиття після if/else)
  - Rightward Degradation (помилки праворуч)
```

### Блок 03: IR-формат
```
03-ir-format.md
  - JSON-схема з прикладами
  - Правила валідації (ir_validator.py)
  - Обмеження: немає координат, немає перетинів
```

### Блок 04: Складні патерни
```

```

## Docs-agent і база знань користувача

`docs-agent` (порт 8767) відповідає за накопичення і пошук предметних знань проекту. Інтерфейс через `NotesTab` у `/docs`:

```
/docs
  ├── Генератор (docs-generator)  — генерація документації з коду
  ├── Нотатки (NotesTab)          — дерево нотаток + пошук
  └── Граф (GraphTab)             — wiki-граф зв'язків між нотатками
```

**Нотатки** — Markdown-файли, що зберігаються і індексуються. Підтримують wiki-links (`[[назва]]`).

**Граф** — автоматично будується з wiki-links між нотатками. Дозволяє навігацію: клік на вузол → відкриває нотатку в редакторі.

## Контекстне використання KB в пайплайнах

При запуску Pipeline A або B агент НЕ отримує всю KB автоматично. Поточна реалізація:
- Системний промпт містить базові правила DRAKON
- Помилки валідації передаються між ітераціями Ralph Loop як контекст
- Предметні знання поки не впливають на генерацію IR

**Майбутнє (Phase 2):** KB-контриб'ютинг через `POST /kb/contribute`. Агент зможе запитувати релевантні нотатки перед генерацією — наприклад, знайти схожий патерн, що вже є в базі.

---

## Принцип накопичення знань

Система дотримується принципу **прогресивної специфікації**:

1. **Перший запуск**: агент робить все за замовчуванням, без предметного контексту
2. **Після ревізії**: розробник зберігає корективи як нотатку або оновлює IR в редакторі
3. **Наступний запуск**: якщо KB буде інтегрована в промпт — агент враховує попередній досвід

Це дозволяє системі **не вимагати великої KB для старту** — вона нарощується органічно з використанням.

## Валідатор IR як частина KB

`drakon-agent/validator/ir_validator.py` — формальна специфікація правил DRAKON, виражена в коді:

```python
def validate_ir(ir: dict) -> ValidationResult:
    errors = []
    # 1. Перевірка обов'язкових полів (name, items)
    # 2. Перевірка наявності термінаторів START/END
    # 3. Перевірка досяжності всіх вузлів (немає orphan nodes)
    # 4. Перевірка посилань (next/yes/no вказують на існуючі id)
    # 5. Перевірка єдиного виходу
    return ValidationResult(valid=not errors, errors=errors)
```

Цей валідатор використовується в Ralph Loop і доступний як MCP-інструмент `drakon.validateir` для зовнішніх клієнтів.
