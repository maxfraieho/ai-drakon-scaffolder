# 01 — Концепція AI-DRAKON

## Проблема, яку вирішує система

Сучасна розробка програмного забезпечення страждає від фундаментального протиріччя: **алгоритмічна логіка мешкає у двох несумісних формах одночасно** — у текстовому коді та в голові розробника. Код є виконуваним, але важко сприймається. Ментальна модель зрозуміла автору, але не передається.

Класичні блок-схеми (ISO 5807, UML) намагалися це вирішити, але зазнали поразки: вони не мають формальних топологічних обмежень, дозволяють перетини ліній та довільне розташування елементів. Результат — діаграми, які неможливо генерувати автоматично і неможливо читати без автора.

**AI-DRAKON** вирішує цю проблему через три принципи:

1. **Строга математична мова** — DRAKON має топологічні інваріанти, що роблять діаграму єдино правильною для даного алгоритму.
2. **Двонаправлений зв'язок** — код конвертується в діаграму (Pipeline A) і діаграма конвертується в код (Pipeline B).
3. **Агент як посередник** — LLM-агенти автоматизують конверсію, залишаючи людині роль архітектора та ревьюера.

---

## Для кого ця система

**Основна аудиторія:** Інженери програмного забезпечення та технічні архітектори, які:
- мають кодові бази, логіку яких потрібно зрозуміти або передати іншим
- проектують нові алгоритми і хочуть валідувати їх до написання коду
- шукають спосіб зробити алгоритмічні рішення частиною технічної документації

**Не є цільовою аудиторією:** менеджери, бізнес-аналітики без технічного бекграунду — DRAKON вимагає розуміння алгоритмічного мислення.

---

## Ключова ідея: алгоритм як перший клас

У традиційному процесі розробки алгоритм існує як артефакт другого класу — він або в коді (неявно), або в документації (застаріє через тиждень). AI-DRAKON перетворює **DRAKON IR** (проміжне представлення діаграми) на перший клас системи:

```
Код  ──Pipeline A──►  DRAKON IR  ──Pipeline B──►  Код
                           │
                     Редактор (UI)
                           │
                    Версіювання (git)
                           │
                   База знань (KB)
```

DRAKON IR — це JSON-структура з вузлами та зв'язками. Вона:
- версіюється разом з кодом
- рендериться редактором без ручного розташування
- валідується автоматично (без перетинів, без мертвих гілок)
- використовується агентами для генерації коду на будь-якій мові

---

## Чому DRAKON, а не UML чи Mermaid

| Критерій | UML/Mermaid | DRAKON |
|----------|-------------|--------|
| Топологічні інваріанти | Відсутні | Строгі (шампур, без перетинів) |
| Автогенерація | Часткова | Повна (IR → рендер детерміновано) |
| Читабельність | Залежить від автора | Гарантована стандартом |
| Машиночитаність | Текстовий DSL | JSON/SQLite IR |
| Інтеграція з LLM | Через DSL-текст | Через структурований IR |
| Підтримка циклів | Произвольна | Строгий паттерн loop_start/end |

Головна перевага DRAKON для AI-систем: **детерміноване відображення логіки**. Один і той самий алгоритм завжди дає одну і ту саму діаграму. Це усуває амбігвалентність при взаємодії з LLM.
