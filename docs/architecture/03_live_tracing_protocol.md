# Фаза 3: Протокол «Живого трасування» — Як схема оживає в UI

У цьому розділі ми розберемо революційну технологію реального часу, яка візуалізує роботу штучного інтелекту безпосередньо на графічній схемі ДРАКОН. Ви дізнаєтеся, як працює зв'язок між бекендом LangGraph та інтерфейсом користувача за допомогою **Server-Sent Events (SSE)**.

---

## 1. Чому Server-Sent Events (SSE) замість REST або WebSockets?

Під час виконання циклічного графа в LangGraph ШІ-модель робить багато кроків: думає, викликає інструменти, аналізує помилки та виправляє свій код. Користувачу вкрай важливо бачити цей прогрес миттєво.

Для реалізації потокового логування ми обрали **SSE (Server-Sent Events)** з кількох причин:

1. **Односпрямованість (Server-to-Client):** На відміну від WebSockets, які потрібні для двостороннього зв'язку (наприклад, у мультиплеєрних іграх), під час трасування графа дані йдуть тільки від сервера до клієнта.
2. **Легковажність та HTTP-сумісність:** SSE працює поверх стандартного протоколу HTTP/1.1 або HTTP/2, не потребує додаткових TCP-з'єднань, проксі-налаштувань або складних рукостискань (handshakes).
3. **Автоматичне перепідключення:** Браузерний клієнт (EventSource) автоматично відновлює зв'язок у разі короткочасного обриву мережі.
4. **Порівняння з REST polling:** Звичайні періодичні REST-запити (наприклад, кожну секунду) створювали б колосальне навантаження на CPU і базу знань. SSE віддає дані миттєво, коли подія відбувається, тримаючи відкритим лише один канал.

---

## 2. Як сервер FastAPI надсилає події виконання графа

Під час запуску графа LangGraph на бекенді, сервер реєструє сесію виконання (Job). Для трансляції кроків у реальному часі використовується генератор, який віддає потокові дані у форматі `text/event-stream`.

Кожна подія завершення кроку графа загортається в структурований JSON і шлеться в ефір:

```http
event: node_done
data: {"node": "code_generator_node", "state": {"attempt_count": 1, "is_valid": false}}

event: node_done
data: {"node": "validator_node", "state": {"is_valid": true}}

event: done
data: {"status": "success"}
```

## 3. Як фронтенд обробляє потік через `usePipelineExecution.ts`

Логіку прослуховування ефіру інкапсульовано в кастомному React-хуці `usePipelineExecution.ts`. Коли користувач натискає кнопку запуску, хук:
1. Викликає REST-метод `startExecution` для отримання унікального `jobId`.
2. Створює підписку `streamExecution`, яка відкриває SSE-канал і починає слухати події.
3. Оновлює внутрішній реактивний стан React.

### Ключові елементи стану:
* `isRunning` (boolean): Чи працює конвеєр у цей момент.
* `activeNode` (string | null): Ім'я вузла, який зараз виконується (або був завершений останнім).
* `completedNodes` (Set<string>): Множина унікальних імен вузлів, які вже успішно завершили свою роботу.
* `breakpointNode` (string | null): Ім'я вузла, перед яким граф зупинився для ручного втручання користувача (Точка зупинки).

## 4. Візуалізація та підсвічування вузлів у `PipelineDrakonView.tsx`

Компонент `PipelineDrakonView.tsx` бере поточний стан виконання (`activeNode`, `completedNodes`, `breakpointNode`) і накладає його поверх графічної схеми ДРАКОН.

### Алгоритм `matchesActiveNode`
Оскільки імена вузлів у LangGraph (наприклад, `"code_generator_node"`) та текстовий вміст іконок ДРАКОН (наприклад, `"Генерація коду"`) можуть дещо відрізнятися, використовується функція розумного мапінгу:

```typescript
// Спрощений приклад функції пошуку відповідності
function matchesActiveNode(item: DrakonItem, activeNodeName: string | null): boolean {
  if (!activeNodeName) return false;
  
  // 1. Пряме порівняння ID іконки
  if (item.id === activeNodeName) return true;
  
  // 2. Порівняння за текстовим контентом іконки (slugify / normalized)
  const normalizedContent = slugify(item.content || "");
  const normalizedNodeName = slugify(activeNodeName);
  
  return normalizedContent === normalizedNodeName || normalizedNodeName.includes(normalizedContent);
}
```

### Кольорова індикація на Canvas
Завдяки стилізації елементів у ДРАКОН-віджеті, кожна іконка отримує інтерактивний клас або колір обводки (stroke) в реальному часі:

```
                  🟢 ЗЕЛЕНИЙ ОБВІД (Виконано)
                   ┌──────────────┐
                   │  Action Node │  (completedNodes.has(item.id))
                   └──────────────┘
                          │
                          ▼
                  🟡 ЖОВТИЙ / БУРШТИНОВИЙ (Активний / Пульсує)
                   ┌──────────────┐
                   │  Action Node │  (activeNode === item.id)
                   └──────────────┘
```

1. **Бурштинний / Жовтий колір (Amber/Yellow + Pulse Effect):** Свідчить про те, що вузол є `activeNode`. Це означає, що ШІ-модель безпосередньо в цей момент виконує завдання всередині цього блоку. На Canvas іконка починає плавно пульсувати, привертаючи увагу користувача.
2. **Зелений колір (Green):** Свідчить про те, що іконка присутня в множині `completedNodes`. Цей етап алгоритму успішно пройдено, результат зафіксовано в глобальному Стані.
3. **Червоний колір (Red):** Свідчить про те, що на даному кроці сталася помилка виконання. Граф зупинено, а деталі помилки виведено в термінальну панель логів.

Завдяки цьому протоколу, виконання складного ШІ-графа перетворюється на захопливий «живий» процес, де користувач бачить кожен рух думки штучного інтелекту!
