# Мануал: Agent Studio — Редактор логіки агентів

## 1. Концепція Agent Studio

**Agent Studio** — це інтерактивний візуальний простір на платформі **AI-DRAKON**, призначений для створення, налаштування та управління поведінкою мультиагентної системи. Основна ідея полягає в тому, що замість написання складних текстових інструкцій розробник може проектувати логіку прийняття рішень LLM-агентами за допомогою візуальних **ДРАКОН-схем**.

---

## 2. Агенти в системі та їхні інтерфейси

В системі розгорнуто три основні класи спеціалізованих агентів, кожен з яких відповідає за свій життєвий цикл розробки:

| Агент | Порт на сервері | Роль та відповідальність |
|-------|-----------------|--------------------------|
| **Architect Agent** | `:8766` | Високорівневий аналіз архітектури коду, планування змін, виділення бізнес-логіки. |
| **Docs Agent** | `:8767` | Робота з базою знань (Knowledge Base), обробка DQL-запитів, генерація технічної документації. |
| **Drakon Agent** | `:8771` | Синтаксична валідація, побудова DRAKON IR графа та генерація коду з візуальних схем. |

Кожен агент може бути налаштований індивідуально за допомогою **системного промпту** (System Prompt), який визначає його характер, стиль кодування та обмеження.

---

## 3. Налаштування логіки через ДРАКОН-схеми

У повноцінному сценарії розробник може прив'язати ДРАКОН-схему безпосередньо до поведінки агента. Схема описує покроковий алгоритм дій агента при отриманні запиту:
1. **Вузол початку** (`Start`) — отримує повідомлення користувача.
2. **Вузли дій** (`Action`) — роблять запити до бази знань або виконують аналіз коду.
3. **Вузли вибору** (`Question`) — аналізують результати попередніх кроків (наприклад, "Чи є в коді помилки?").
4. **Вузол завершення** (`End`) — повертає фінальну відповідь у чат.

> **ЗВІТ ПРО РЕАЛЬНИЙ СТАН ФРОНТЕНДУ (на основі автоматизованих тестів від 2026-05-26):**
> 
> Під час виконання повного циклу автоматизованого тестування інтерфейсу за допомогою PinchTab було виявлено серйозні розбіжності між запланованою архітектурою та її фактичною реалізацією у графічному інтерфейсі користувача. 

### Виявлені проблеми та баги (Bug Catalog):
1. **BUG-6 (TEST-AGENT-01) — Відсутність інтерфейсу чату на `/agents`**:
   * *Очікувалось*: Повноцінний інтерактивний чат-інтерфейс з активними агентами.
   * *Фактично*: Поле вводу чату (`textbox`) та кнопка відправки повідомлення не відрендерилися на сторінці `/agents`. Сторінка містить лише статичний опис агентів без можливості взаємодії.
2. **BUG-8 (TEST-AGENT-03) — Відсутність вкладки DRAKON-редактора**:
   * *Очікувалось*: Наявність вкладки "Схема" або "DRAKON Logic" для візуального редагування алгоритмів поведінки агентів.
   * *Фактично*: У поточній версії frontend-інтерфейсу `/agents` повністю відсутній візуальний компонент DRAKON-редактора для логіки агентів.

> **Примітка**: BUG-6 виправлено (AgentChatPanel підключено до /agents). BUG-7 виправлено (кнопка «+» додана до PipelineList).

### Тимчасовий обхідний шлях (Workaround) для розробників:
Наразі налаштування поведінки агентів та тестування їхніх можливостей рекомендується виконувати:
* Прямо через **MCP-інструменти** (інструмент `agent.chat` для взаємодії з архітектурним агентом).
* Шляхом ручного редагування конфігураційних файлів промптів у директорії `/home/vokov/workspace/ai-drakon-scaffolder/.agents/`.
* Перевіркою візуальних графів безпосередньо у загальному редакторі схем `/diagrams` з подальшим імпортом у логіку через конфіг.
