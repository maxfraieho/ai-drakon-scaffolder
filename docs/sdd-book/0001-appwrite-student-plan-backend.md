# 0001. Використовувати Appwrite Student Plan як бекенд-платформу для ШІ-агентів, автентифікації та бази даних

## Контекст і формулювання проблеми
Проєкт `ai-drakon-scaffolder` вимагає надійного бекенд-оточення для запуску спеціалізованих ШІ-агентів (`Docs-Agent`, `Architect-Agent`), фонових задач кодогенерації (`drakon-codegen`), побудови семантичного графу (`semantic-graph`) та детерміністичного рушія (`deterministic-engine`). Окрім обчислювальних функцій, системі необхідні готові механізми автентифікації користувачів (Auth) та централізоване сховище метаданих/документів (Database).

Розгортання та самостійне супроводження розрізненої інфраструктури для невеликої команди чи індивідуального розробника створює значний операційний оверхед. Необхідно було обрати платформу, яка мінімізує витрати на налаштування інфраструктури, надаючи єдину екосистему для Auth, DB та Serverless функцій.

## Рушії рішення
- **Комплексність "з коробки"**: Наявність готових інтегрованих інструментів автентифікації (Auth), документної бази даних (DB) та середовища виконання Serverless Functions в одному керованому сервісі.
- **Оптимізоване середовище для ШІ-агентів**: Можливість швидкого розгортання та ізольованого запуску коду агентів (`Docs-Agent`, `Architect-Agent`, `drakon-codegen`) без ручного керування серверами.
- **Економічна ефективність та простота адміністрування**: Доступність тарифного плану Student Plan, який надає достатні ліміти для розробки та прототипування без складного білінгу та високих фінансових витрат.

## Розглянуті варіанти
1. **Appwrite Student Plan** (обраний варіант)
2. **Традиційні хмарні функції (AWS Lambda + AWS Cognito + DynamoDB/RDS)** (альтернатива з таблиці)
3. **Supabase Cloud (PostgreSQL + Supabase Auth + Edge Functions)** (додатковий розглянутий варіант для повноти)

## Підсумок рішення
Обрано **Appwrite Student Plan** як основну платформу Backend-as-a-Service (BaaS) для автентифікації, збереження структурованих даних і виконання серверлес-функцій ШІ-агентів.

### Наслідки
- **Позитивні:**
  - Швидкий старт розробки завдяки єдиному SDK для авторизації, доступу до бази та виклику функцій.
  - Ізольоване виконання мікросервісів агентів у керованому середовищі Appwrite Cloud Functions.
  - Зведення до нуля витрат на адміністрування серверної інфраструктури, оновлення ОС та масштабування бази даних.
- **Негативні:**
  - Прив'язка до API та SDK Appwrite (vendor lock-in).
  - Жорсткий 15-хвилинний TTL для клієнтських JWT токенів Appwrite (вимагає вирішення на рівні шлюзу/проксі).
  - Наявність затримок холодного старту (cold starts) при виклику серверлес-функцій.

## Плюси і мінуси варіантів

### Appwrite Student Plan
* Добре: Всі необхідні сервіси (Auth, DB, Functions) доступні в єдиному інтерфейсі та SDK.
* Добре: Зручний локальний та хмарний деплой функцій для агентів (`Docs`, `Architect`, `drakon-codegen`).
* Добре: Безкоштовний/пільговий доступ у межах студентської програми з достатніми ресурсами.
* Погано: Короткий час життя JWT токенів (15 хвилин), що ускладнює прямі довгі сесії без рефрешу.
* Погано: Cold start при рідкісних викликах агентських функцій.

### Традиційні хмарні функції (AWS Lambda + Cognito + DynamoDB)
* Добре: Промисловий стандарт надійності, практично безмежне масштабування.
* Добре: Гнучке налаштування мережевих правил (VPC), IAM політик та тригерів.
* Погано: Висока складність конфігурації (CloudFormation/Terraform, IAM roles, API Gateway).
* Погано: Вимагає значних часових витрат на адміністрування та моніторинг.
* Погано: Складніший і потенційно непередбачуваний білінг навіть для пет-проєктів.

### Supabase Cloud (PostgreSQL + Auth + Edge Functions)
* Добре: Повноцінна реляційна база даних PostgreSQL з підтримкою SQL та векторного розширення `pgvector`.
* Добре: Зручна Deno-орієнтована екосистема Edge Functions.
* Погано: Потребує складнішого налаштування Row Level Security (RLS) для взаємодії бекенд-агентів.
* Погано: Менш зручна інтеграція для сценаріїв ізольованого виконання важких Python/Node.js скриптів кодогенерації у порівнянні з класичними контейнерними рантаймами Appwrite Functions.

## Додаткова інформація
Рішення реконструйовано на основі архітектурної документації `MASTER-CONTEXT.md`.
