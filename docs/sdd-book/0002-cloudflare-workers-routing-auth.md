# 0002. Використовувати Cloudflare Workers для глобальної маршрутизації, підпису S3-запитів та обходу обмежень JWT

## Контекст і формулювання проблеми
Клієнтський застосунок `ai-drakon-scaffolder` (розгорнутий на Cloudflare Pages) взаємодіє з різними бекенд-сервісами: Appwrite Cloud Functions, сховищем об'єктів MinIO S3 та локальними/віддаленими FastAPI мікросервісами (порти 8765–8767). 

Виникли три ключові архітектурні виклики:
1. Клієнтські токени Appwrite JWT мають жорсткий ліміт дії у 15 хвилин, що призводить до обриву сесій або необхідності складної логіки повторної авторизації на фронтенді.
2. Прямі звернення до функцій Appwrite для простої маршрутизації та проксіювання викликають небажані затримки через холодні старти (cold starts).
3. Доступ до об'єктного сховища MinIO S3 потребує безпечного формування підписаних URL (presigned S3 signatures) без розкриття приватних ключів доступу клієнту.

## Рушії рішення
- **Миттєва глобальна маршрутизація (Edge Routing)**: Забезпечення мінімального часу відгуку при проксіюванні запитів до API без затримок холодного старту.
- **Підпис S3-запитів до MinIO**: Безпечна генерація S3-сумісних підписів для завантаження та отримання файлів безпосередньо на edge-рівні.
- **Обхід 15-хвилинного ліміту Appwrite JWT**: Централізоване керування сесіями, валідація та прозоре оновлення/обмін токенів на рівні шлюзу.

## Розглянуті варіанти
1. **Cloudflare Worker (`drakon-antigravity-worker`)** (обраний варіант)
2. **Маршрутизація всередині функцій Appwrite** (альтернатива з таблиці)
3. **Виділений API Gateway (FastAPI / Nginx / Node.js)** (додатковий розглянутий варіант для повноти)

## Підсумок рішення
Обрано **Cloudflare Workers** (воркер `drakon-antigravity-worker`) як глобальний edge-проксі та шлюз безпеки для авторизації, підпису S3-запитів до MinIO та диспетчеризації викликів до Appwrite і FastAPI мікросервісів.

### Наслідки
- **Позитивні:**
  - Нульовий холодний старт для операцій маршрутизації та перевірки прав доступу.
  - Повна ізоляція приватних ключів MinIO S3 на рівні Cloudflare Secrets.
  - Безшовна робота клієнта без збоїв через закінчення 15-хвилинного TTL Appwrite JWT.
  - Єдина точка входу (`workerUrl()`) для фронтенду, що спрощує CORS та конфігурацію клієнта.
- **Негативні:**
  - Додаткова ланка в архітектурі, яку необхідно розгортати та підтримувати окремо (`wrangler`).
  - Обмеження середовища виконання V8 Isolate (відсутність стандартних нативних модулів Node.js без поліфілів).
  - Ліміти безкоштовного тарифу Cloudflare Workers за кількістю щоденних запитів та процесорним часом.

## Плюси і мінуси варіантів

### Cloudflare Worker (`drakon-antigravity-worker`)
* Добре: Розподілена edge-мережа з наднизькою затримкою у будь-якій точці світу.
* Добре: Відсутність cold starts порівняно зі звичайними serverless-контейнерами.
* Добре: Зручна нативна підтримка обробки заголовків, криптографічного підпису S3 та маніпуляцій з JWT.
* Погано: Специфічний рантайм Service Worker / Fetch API, що вимагає специфічного тестування.
* Погано: Необхідність синхронізації змін між кодом воркера та клієнтськими типами.

### Маршрутизація всередині функцій Appwrite
* Добре: Відсутність необхідності підключати окремого хмарного провайдера (Cloudflare).
* Добре: Прямий доступ до внутрішнього контексту та БД Appwrite.
* Погано: Висока затримка відповіді через регулярні холодні старти серверлес-функцій.
* Погано: Неможливість ефективно вирішити проблему 15-хвилинного ліміту JWT для вхідного трафіку.
* Погано: Марнотратне використання лімітів обчислювального часу Appwrite на тривіальні задачі проксіювання.

### Виділений API Gateway (FastAPI / Nginx на окремому сервері)
* Добре: Повний контроль над середовищем виконання, відсутність обмежень на час виконання чи розмір пам'яті.
* Добре: Можливість спільного розміщення з локальними FastAPI сервісами (порти 8765–8767).
* Погано: Необхідність адміністрування власного сервера/VPS, моніторингу аптайму та налаштування SSL/TLS.
* Погано: Відсутність географічного розподілу (затримка для віддалених клієнтів вища, ніж на Cloudflare Edge).

## Додаткова інформація
Воркер `drakon-antigravity-worker` обслуговує ендпоінти API, зокрема `/v1/codegen`, `/v1/codegen-status`, маршрутизує запити до агентів та забезпечує підписаний доступ до сховища схем алгоритмів MinIO.
