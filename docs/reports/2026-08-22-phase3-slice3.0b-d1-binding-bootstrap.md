## 6. Exact schema change

```diff
 CREATE INDEX IF NOT EXISTS idx_runs_tenant ON pipeline_runs(tenant_id, started_at);
+
+CREATE TABLE IF NOT EXISTS harness_specs (
+  id           TEXT PRIMARY KEY,
+  tenant_id    TEXT NOT NULL,
+  agent_name   TEXT NOT NULL,
+  -- дублює DrakonHarnessSpec.version (TEXT у контракті, packages/harness-contract)
+  version      TEXT NOT NULL,
+  -- серіалізований DrakonHarnessSpec цілком
+  spec_json    TEXT NOT NULL,
+  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
+  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
+  UNIQUE (tenant_id, agent_name, version)
+);
+CREATE INDEX IF NOT EXISTS idx_harness_specs_tenant
+  ON harness_specs(tenant_id, agent_name);
```

Column rationale, derived from the existing file's own conventions and the real `DrakonHarnessSpec` contract type (`packages/harness-contract/src/index.ts:26-29`), not invented ad hoc:
- `id` / `tenant_id`: same `TEXT PRIMARY KEY` / `TEXT NOT NULL` shape as every other table in this file.
- `agent_name`: matches the contract's own `agent_name: string` identity field, and mirrors `agent_configs`' existing column of the same name/purpose.
- `version TEXT` (not `INTEGER`): the contract declares `version: string`, so the column type matches the payload it will actually hold, avoiding a silent type mismatch between DB and app.
- `spec_json`: follows the file's existing `_json`-suffix convention for serialized payloads (`drakon_ir_json`, `zones_json`, `ir_json`).
- `created_at`/`updated_at`: same `datetime('now')` default pattern used elsewhere.
- `UNIQUE (tenant_id, agent_name, version)` + `idx_harness_specs_tenant`: mirrors `agent_configs`' `UNIQUE (tenant_id, agent_name)` + tenant index pattern, extended with `version` since a spec can have multiple versions per agent.

No other table added (`run_events`, `specs`, `adrs`, `task_graphs` — all explicitly out of scope per the coordinator prompt, left untouched).

- ❌ **`ROOM_DO` (Durable Object binding, class `RoomDO`) — present before this deploy, absent after.** `worker-wrangler.toml` never declared a `durable_objects` section (only `cloudflare-worker/wrangler.toml`, an explicitly out-of-scope file for this slice, declares `ROOM_DO`/`DIAGRAM_SYNC`). Deploying with a config that omits a Durable Object binding removed it from the live Worker.

This is a genuine violation of Step 7's explicit requirement ("no unintended bindings disappeared") and Step 3's constraint ("do not modify unrelated bindings"). The deployment audit's own live-metrics check (§4, prior slice) showed `RoomDO` completely idle — 0 invocations, 0 storage, 0 WebSocket messages across the full metrics window checked — so the practical blast radius is very likely near-zero. But it is a real, unintended removal of a live production resource caused by this slice's authorized deploy action, not something explicitly sanctioned by the coordinator prompt, and it is not something this report will silently paper over or silently fix by guessing which way to resolve it.

**Follow-up fix (same slice, second pass after a session resume):** re-verified live state was unchanged from the point above, then restored `ROOM_DO` by adding a `[[durable_objects.bindings]]` block (`name = "ROOM_DO"`, `class_name = "RoomDO"`) to `cloudflare-worker/worker-wrangler.toml` — no new migration tag needed, since the `RoomDO` class was already provisioned under this Worker script's deploy history (via the other, out-of-scope config's earlier `v1` migration); Wrangler only needed the binding re-declared to reattach it. Redeployed with the same command as §8. Result: `REAL_EXIT=0`. Wrangler printed a non-blocking warning suggesting a newer `[exports.RoomDO]`/`storage = "sqlite"` config convention be added for full forward-compatibility — noted as a follow-up nicety, not required for this deploy to succeed. Post-redeploy live API re-read confirms `ROOM_DO` is back with **the exact same `namespace_id` as before this slice began** (`58bd48cb659d481292fe2bf8bdb433ca`) — i.e. the same Durable Object namespace was reattached, not recreated; no data loss.
