# 🎯 AI-DRAKON — Master Context

Останнє оновлення: 2026-06-30 05:45 (EEST)

## 📦 Проект
- **Що це:** Платформа для розробки ПЗ на основі візуальних схем ДРАКОН з інтеграцією ШІ-агентів. Користувач описує алгоритм природною мовою → LLM генерує ДРАКОН-схему (JSON) → схема редагується у графічному редакторі та компілюється в робочий код.
- **Мета:** Створити інтегроване середовище, де ШІ допомагає перетворювати вимоги у візуальні алгоритми, які компілюються у браузері (JS/Lua) та надійно зберігаються у GitHub репозиторії користувача.
- **Стек:** 
  * **Frontend:** React, Vite, TypeScript, Tailwind CSS, TanStack Router (деплой на Cloudflare Pages з `.lovable/src/`).
  * **Gateway:** Cloudflare Worker (`drakon-antigravity-worker`) для авторизації та проксіювання запитів.
  * **Backend & Auth:** Appwrite Cloud (база даних, сесії користувачів).
  * **Агенти (Appwrite Functions):** Docs-Agent (аналіз вимог/docs), Architect-Agent (проектування solution.json), drakon-codegen (генерація схем), deterministic-engine (детерміноване виконання пайплайнів).
  * **Рантайм & Код:** FastAPI мікросервіси на сервері розробки (порти 8765, 8766, 8767), клієнтські збірки `drakontechgen.js` та `drakongen.js`.
  * **Сховище:** MinIO S3 (бакети для діаграм та логів).

## 🏗 Архітектурні рішення

| Рішення | Чому прийнято | Альтернативи |
|---|---|---|
| **Appwrite Student Plan** | Надає готові інструменти Auth, DB та Serverless функції для запуску ШІ-агентів (Docs/Architect). | Традиційні хмарні функції (AWS Lambda), які складніше адмініструвати та конфігурувати. |
| **Cloudflare Workers** | Забезпечує миттєву глобальну маршрутизацію, підпис S3-запитів до MinIO та обхід 15-хвилинного ліміту Appwrite JWT. | Маршрутизація всередині функцій Appwrite, що збільшило б затримку через cold starts. |
| **GitNexus** | Використовується як семантичний граф коду для розрахунку blast radius змін перед редагуванням та аналізу зв'язків. | Стандартний текстовий grep, який не має контексту структури коду та викликів функцій. |

## 🔌 Інфраструктурні MCP-сервери та можливості rpi3b

### 🛠️ Можливості вузла rpi3b (dev-сервер):
- **Служби та Бази Даних:** Хостинг векторної БД MemPalace (ChromaDB) на порту `49374` та Code Intelligence бази GitNexus на порту `4747`.
- **Backend-сервіси:** Усі FastAPI мікросервіси (`architect-agent` на порту `8766`, `drakon-agent` на порту `8765`, `docs-agent` на порту `8767`) перевірені та повністю працездатні.
- **Хмарні функції:** `deterministic-engine` успішно скомпільований та розгорнутий як Appwrite Function.

### 🔌 Доступні MCP-сервери (Model Context Protocol):
- **GitNexus MCP (`gitnexus`):** Повний аналіз зв'язків у коді, визначення blast radius змін (`impact`), семантичний пошук та виявлення регресій (`detect_changes`).
- **MemPalace MCP (`mempalace`):** Збереження та пошук контексту розробки, ведення та читання щоденників агентів (`diary_write`/`diary_read`), керування фактами.
- **NotebookLM MCP (`notebooklm`):** Створення та аналіз блокнотів, робота з великими обсягами документації.

## 🧪 Протокол тестування (наступний крок)
1. **Сценарій 1:** Створення проекту та перевірка графа знань (TASK-DRK-21). Перевірка автоматичної ініціалізації та пушу `.understand-anything/knowledge-graph.json` на GitHub.
2. **Сценарій 2:** Робота в Agent Studio, EVIDENCE Panel та Runtime (TASK-DRK-20/22). Перевірка гарячих клавіш Ctrl+S, аналізу впливу в EVIDENCE панелі та детермінованого виконання через `usePipelineExecution` при `VITE_USE_DETERMINISTIC=true`.
3. **Сценарій 3:** Декомпозиція додатку через PlayPipe (UI-3.1/3.2). Перевірка ШІ-генерації графів компонентів та моніторингу статусів збірки через SSE.
4. **Сценарій 4:** Дизайн воркфлоу n8n та Deploy (UI-4.1/4.2). Перевірка інтерактивного налаштування параметрів n8n-вузлів у сидебарі та пушу воркфлоу на сервер.
