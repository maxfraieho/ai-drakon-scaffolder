# Промт для Gemini: Глибоке дослідження та створення спеціалізованої бази знань для DRAKON-агента

## Контекст завдання

Ти — провідний дослідник у галузі мов візуального програмування та AI-систем.
Ти отримуєш **6 PDF-документів** про мову DRAKON та платформу AI-DRAKON.
Твоє завдання — провести глибоке дослідження і створити **спеціалізовану базу знань (Knowledge Base)** у форматі набору Markdown-файлів.

Ця база знань **не для людей** — вона для **LLM-агента (drakon-agent)**, який:
1. Отримує "сирий" DRAKON IR, згенерований автоматичним AST-аналізатором Python-коду
2. Використовує BM25 для пошуку релевантних правил (за ключовими словами)
3. Отримує знайдені правила як контекст у свій промт
4. Покращує IR до вигляду, зрозумілого людині: правильні підписи іконок, правильна структура, правильний тип діаграми

**Технічний стек:**
- Python AST → `action`/`question`/`branch`/`end` вузли DRAKON IR (JSON, flat dict)
- Виджет: `drakonwidget.js` від Степана Міткіна
- IR формат: `{ "name": "...", "params": "...", "items": { "b0": {...}, "n1": {...}, "end": {...} } }`
- `b0` = обов'язковий entry branch (branchId: 0, one → перший вузол)
- `action.one` → наступний вузол; `question.one` → YES (true), `question.two` → NO (false)

Ретельно вивчи всі 6 PDF і дай відповідь на такі питання (використовуй їх як основу для KB):

5. Коли функцію варто розбити на кілька гілок Silhouette замість одного Primitive?

### Блок 2: Іконки DRAKON та їх семантика

Для кожного типу іконки DRAKON надай:
- Офіційна назва (ukr/eng)

### Блок 3: Правила "людиночитаємого" підпису іконок

Це НАЙВАЖЛИВІШИЙ блок для агента. LLM повинен знати:

1. **Дія (action):** Як перетворити Python-рядок коду на короткий дієслівний підпис?
   - `result = process_data(items)` → `Обробити дані елементів` чи `result = process_data(items)`?
   - `raise ValueError("not found")` → `Викинути помилку: значення не знайдено`?
   - `return None` → `Повернути None` чи `Повернути порожнє значення`?
   - Правило: мова (укр/рос/eng) залежить від мови коду чи від налаштувань?
   - Правило: максимальна довжина підпису дії (символів)?

2. **Умова (question):** Правила формулювання умови у запитальній формі
   - `if not name:` → `Ім'я порожнє?` чи `not name?` чи `name є None або ""?`
   - `if x > threshold and retry < max_retries:` → як скоротити складну умову?
   - `for item in items:` → `Ще є елементи в items?` чи `item in items?`
   - `while running:` → `running = True?` чи `Система продовжує роботу?`
   - Правило: умова завжди закінчується `?`?

3. **Гілка Silhouette (branch/column header):** Як назвати гілку?
   - Правило іменування для try/except гілок
   - Правило для guard clauses (if x: return early)
   - Правило для happy path vs error path

### Блок 4: Маппінг Python AST → DRAKON IR

Для кожної Python конструкції надай правило маппінгу:

| Python AST | DRAKON тип | Примітки |
|-----------|-----------|---------|
| `ast.Assign`, `ast.AugAssign` | action | ... |
| `ast.If` (з else) | question | ... |
| `ast.If` (без else) | question | two → merge |
| `ast.If` (elif chain) | вкладені questions | ... |
| `ast.For` | question | "Ще є елементи?" |
| `ast.While` | question | умова циклу |
| `ast.Return` | action | → end |
| `ast.Raise` | action | → end або error branch |
| `ast.Try/except` | question | "Виняток виник?" |
| `ast.FunctionDef` | окрема діаграма | b0 + end |
| `ast.ClassDef` → методи | окремі діаграми | name = "ClassName.method" |

Специфічні питання:
- Як правильно зобразити `try/except/finally` у DRAKON?
- Як зобразити `for/else` або `while/else`?
- Що робити з вкладеними функціями (lambda, def всередині def)?
- Як зобразити list comprehension?

### Блок 5: Принцип "правого зміщення" (Rightward Degradation)

1. Що таке rightward degradation у DRAKON?
2. Як визначити "happy path" автоматично із Python-коду?
   - Евристика 1: найдовша гілка без виходів за допомогою return/raise = happy path?
   - Евристика 2: гілка з найбільшою кількістю вузлів = happy path?
   - Евристика 3: `question.one` (YES) = завжди happy path?
3. Яка гілка питання (one/two) за правилами DRAKON є happy path?
   - `question.one` = YES = happy (condition is TRUE = continue) — правило номер 1?
   - `question.two` = NO = error/alternative (condition is FALSE = exit/error)?
4. Практичні приклади: `if not valid: return error` — це guard clause. Чому `two` тут веде до happy path?

### Блок 6: Метрики якості та валідація

1. SIS (Single-Item Skewer) — що це і як рахується?
2. RDC (Rightward Degradation Coefficient) — що це і як рахується?
3. Які значення SIS/RDC вважаються "добрими"?
4. Перелік помилок валідатора та їх виправлення:
   - Немає b0 → як виправити
   - question без two → як виправити
   - Недосяжні вузли → як виправити
   - Циклічні залежності без виходу → як виправити

### Блок 7: Типові патерни Python → DRAKON

Надай готові шаблони IR для:
1. **Guard clause pattern** (if x: return early)
2. **Try/catch error handling** (try/except/finally)
3. **Loop with break** (for/while з break та continue)
4. **Strategy pattern** (if/elif/elif/else ланцюжок)
5. **Pipeline pattern** (послідовність перетворень даних)
6. **Recursive function** (рекурсія — чи є правила для DRAKON?)

### Вимоги до кожного файлу

**Структура секцій:** Використовуй `## Heading` (саме так — BM25 ділить за цим)

**Стиль тексту для BM25-оптимізації:**
- Кожна секція = набір конкретних правил, не есе
- Ключові слова повторюються природньо (action, question, content, happy path, skewer...)
- Без вступних абзаців типу "У цьому розділі ми розглянемо..."
- Правила у вигляді bullet points або numbered list
- Приклади у форматі: `Python код → DRAKON content рядок`

**JSON приклади:** Показуй повний IR для кожного патерну

**Мова:** Українська, технічні терміни — англійська (action, question, branch, skewer, silhouette)
