# 📊 Плейбук ручного тестування платформи AI-DRAKON

Цей документ містить покрокові сценарії ручного тестування інтерфейсу користувача платформи AI-DRAKON та аналіз відповідності її компонентів меті проекту.

---

## 🛠️ Оцінка інтеграції інтерфейсу в загальну систему

Платформа призначена для спрощення розробки програмного забезпечення на основі візуальних схем ДРАКОН з інтеграцією ШІ-агентів. Інтерфейс розподілений за трьома основними режимами роботи:

| Компонент / Маршрут | Цільове призначення | Архітектурна інтеграція під капотом |
| :--- | :--- | :--- |
| **New Project Wizard**<br>`/project/new` | Швидкий старт проекту та інтеграція з GitHub. | Викликає Cloudflare Worker (`/v1/github/commit`). Автоматично ініціалізує граф знань `.understand-anything/knowledge-graph.json` (**TASK-DRK-21**). |
| **Project Overview**<br>`/p/$slug/overview` | Зведення інформації про проект та поточний режим. | Запитує конфігурацію проекту з бази даних Appwrite (`getProject(slug)`). Відображає поточні метадані та статус інтеграції. |
| **Agent Studio / Editor**<br>`/p/$slug/agents/$id/studio` | Візуальне проектування логіки ШІ-агентів через ДРАКОН-схеми. | Рендерить `DrakonEditor`. Зберігає схеми локально та коммітить у GitHub. Звертається до FastAPI сервісу `drakon-agent` на порту 8765. |
| **EVIDENCE Drawer**<br>(Нижня панель у DrakonEditor) | Зворотний зв'язок компілятора та аналіз впливу змін. | Інтегрується з сервісом **Understand-Anything** (**TASK-DRK-20**). Вираховує blast radius змін та виводит звіт у реальному часі. |
| **Runtime Target Toggle** | Вибір середовища виконання (`flue` або `eve`). | Додає параметри виконання в схему ДРАКОН (`schema.state_class`). Дозволяє експортувати ZIP-архів для EVE рантайму. |
| **Decomposition Wizard**<br>`/p/$slug/playpipe` | ШІ-декомпозиція великої задачі на менших агентів. | Надсилає запит на `api.decomposeApp`. Формує чергу компонентів та візуалізує граф залежностей збірки. |
| **Build Progress Panel (SSE)**<br>`/p/$slug/playpipe/build` | Моніторинг збірки агентів у реальному часі. | Підключається до SSE-сервісу (`/v1/pipeline/stream/{jobId}`) на Cloudflare Worker для відстеження статусів компонентів. |
| **N8N Automations Page**<br>`/p/$slug/automations` | Візуальне програмування воркфлоу n8n. | Використовує `N8NNodeSidebar` для конфігурації параметрів вузлів. Зберігає схеми та пушить готові воркфлоу у локальний/віддалений n8n. |

---

## 🧪 Сценарії тестування (Тест-кейси)

### Сценарій 1: Створення проекту та перевірка графа знань (TASK-DRK-21)
**Мета:** Перевірити автоматичну генерацію та пуш початкового файлу `knowledge-graph.json` на GitHub.

1. **Крок 1:** Перейдіть на головну сторінку `/` (ви маєте бути авторизовані).
2. **Крок 2:** Натисніть кнопку **New Project** (`#new-project-btn`).
3. **Крок 3:** Заповніть форму створення проекту:
   * **Назва:** `UAV Test Flight`
   * **Опис:** `A project to test target detection workflows.`
   * **Режим:** `Agent`
4. **Крок 4:** Переконайтеся, що налаштована GitHub-інтеграція (Owner/Repo). Натисніть **Create Project**.
5. **Крок 5 (Верифікація):** 
   * Перейдіть у створений проект, оберіть вкладку **Knowledge Graph** (або перегляньте файлову структуру в репозиторії).
   * **Очікуваний результат:** У вашому репозиторії на GitHub та в інтерфейсі має відобразитися файл `.understand-anything/knowledge-graph.json` з базовою кореневою нодою `root-project`.

---

### Сценарій 2: Робота в Agent Studio, EVIDENCE Panel & Runtime (TASK-DRK-20 / 22)
**Мета:** Перевірити збереження схем, аналіз впливу та перемикання рантайму.

1. **Крок 1:** У створеному проекті перейдіть у вкладку **Agents** та відкрийте існуючого агента в **Studio** (`Open in Studio`).
2. **Крок 2:** Перевірте роботу **Runtime Target Toggle**:
   * Перемкніть рантайм на **EVE**. Перевірте наявність кнопки експорту ZIP.
   * Перемкніть назад на **Flue**.
3. **Крок 3:** Внесіть косметичну зміну у вузол дії на схемі та натисніть гарячі клавіші **Ctrl+S** (або кнопку **Save**).
4. **Крок 4 (Верифікація EVIDENCE):**
   * Відкрийте нижню панель **EVIDENCE** (якщо вона згорнутя).
   * **Очікуваний результат:** Панель має вивести статус компіляції та провести аналіз впливу (blast radius) змін, вказавши пов'язані вузли, на які впливає змінений вами вузол.

---

### Сценарій 3: Декомпозиція додатку через PlayPipe (UI-3.1 / 3.2)
**Мета:** Перевірити ШІ-декомпозицію та моніторинг збірки через SSE.

1. **Крок 1:** Створіть новий проект або перемкніть існуючий у режим **PlayPipe**.
2. **Крок 2:** Перейдіть у вкладку **PlayPipe**.
3. **Крок 3:** У текстове поле введіть опис: 
   * *`"A chatbot that analyzes logs from Appwrite functions, detects errors, and alerts Telegram."`*
4. **Крок 4:** Натисніть **Decompose** і зачекайте завершення аналізу.
5. **Крок 5:** Перевірте, що на екрані з'явився граф декомпозиції (Component Dependency Graph). Призначте агента на один з компонентів.
6. **Крок 6:** Натисніть **Start Build**.
7. **Крок 7 (Верифікація):** 
   * Вас має перенаправити на сторінку `/p/$slug/playpipe/build?buildId=...`.
   * **Очікуваний результат:** Ви маєте бачити картки збірки кожного компонента, статус яких змінюється в реальному часі за рахунок отримання SSE подій (`node_done`, `done`).

---

### Сценарій 4: Дизайн воркфлоу n8n та Deploy (UI-4.1 / 4.2)
**Мета:** Створення візуальної інтеграції та пуш у локальний n8n.

1. **Крок 1:** Створіть/відкрийте проект у режимі **n8n** та перейдіть у вкладку **Automations**.
2. **Крок 2:** Створіть нову автоматизацію.
3. **Крок 3:** Клацніть на вузол дії. Впевністься, що справа відкрився **N8NNodeSidebar**.
4. **Крок 4:** Налаштуйте параметри вузла (наприклад, тип вузла `Telegram`, введіть `chatId` та `text`).
5. **Крок 5:** Збережіть схему.
6. **Крок 6 (Верифікація):** 
   * Натисніть кнопку **Push to n8n** (або перевірте статус підключення в налаштуваннях).
   * **Очікуваний результат:** Воркфлоу має успішно імпортуватися у ваш налаштований n8n сервер, а в інтерфейсі з'явиться статус успішного розгортання (`Pushed`).
