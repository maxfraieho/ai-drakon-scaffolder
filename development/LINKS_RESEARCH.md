# Дослідження оптимальної щільності зв'язків у Knowledge Graph (TASK-18)

## 1. Оптимальна кількість вихідних зв'язків (Outgoing Links) на документ

Для стандартного документа бази знань обсягом 100–500 слів оптимальною є кількість **3–5 вихідних зв'язків**.
- **Більше 5 зв'язків** створює "візуальний шум", розсіює увагу читача та перевантажує граф зв'язків (спричиняє over-linking).
- **Менше 2 зв'язків** може призвести до утворення ізольованих сторінок ("dead ends").

### Конкретні правила генерації wiki-зв'язків для AI-агента:
1. **Правило критичного контексту (Critical Context Rule)**: Додавати зв'язок `[[ім'я_файлу]]` лише тоді, коли розуміння цільового документа є критичним для сприйняття поточного. Не лінкувати загальновідомі терміни чи інструменти.
2. **Правило єдиного входження (Single Occurrence Rule)**: Кожна унікальна сторінка має згадуватися як лінк лише один раз на документ (бажано при першій згадці або в спеціальному розділі).
3. **Локалізація лінків (Local Links Isolation)**: Усі навігаційні лінки мають бути консолідовані в кінці документа в секції `## Семантичні зв'язки`. В основному тексті лінки допускаються лише для конкретних API або модулів.
4. **Бюджет посилань (Link Budget)**: Жоден стандартний документ не повинен перевищувати ліміт у 4 вихідні зв'язки.

## 2. Правила лінкування для чистих графів (~60 документів)

Для невеликої бази знань (~60 документів), яка має теги доменів та рівні ієрархії (Tiers), діють такі принципи:

### Коли створювати зв'язок:
- **Upward (Вгору)**: Обов'язкове посилання на батьківський індекс (`_INDEX.md` або концепт-хаб поточного розділу). Це забезпечує ієрархічну зв'язність.
- **Sequential (Послідовно)**: Посилання на наступний логічний крок процесу (наприклад, `[[Read Next: ...]]`), якщо документи описують фази або кроки.
- **Dependency (Залежність)**: Посилання на модуль або концепт, від якого поточний документ безпосередньо залежить (імпорти, спільна шина даних).

### Коли пропускати (omitted) зв'язок:
- Якщо цільовий документ лежить в іншому домені і не має прямого зв'язку з поточною задачею.
- Якщо цільовий документ уже доступний через 1 крок (hop) через батьківський індекс (пропускаємо надлишкові горизонтальні зв'язки між сусідами, якщо вони не залежать один від одного).
- Якщо це створює циклічну петлю без семантичної цінності.

---

## 3. Мінімальні правила обмеження до 3-4 зв'язків

Замість складної обов'язкової структури (parent + related + read-next) впроваджується **жорсткий бюджет зв'язків (max 3-4)**:

1. **Висхідний (Upward)** — 1 лінк на батьківський індекс (наприклад, `[[docs/plans/_INDEX]]`).
2. **Послідовний (Read-Next)** — максимум 1 лінк на наступний крок (якщо є).
3. **Суміжні зв'язки (Related)** — максимум 1-2 лінки на найбільш критичні суміжні документи.

Загальна сума вихідних посилань у секції `## Семантичні зв'язки` не повинна перевищувати 4.
