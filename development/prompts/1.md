# AI-DRAKON — Промт для покращення зручності роботи та наступних кроків

## Контекст

Проведено QA-перевірку платформи AI-DRAKON за чек-листом DRK-1..12. Виправлена критична проблема DRK-9 (валідація тепер блокує коміт при структурних помилках). Решта пунктів чек-листа реалізована на рівні коду. Нижче — промт для агента (або розробника), який покращить зручність роботи з системою та врахує необхідні зміни.

---

## ПРОМТ

Ти — технічний асистент проекту AI-DRAKON. Працюєш як developer + UX-інженер.
Метою є покращення зручності (UX) та надійності роботи з платформою.

### КОНТЕКСТ ПРОЕКТУ
- Frontend: React + TanStack Router, деплой на Cloudflare Pages (build з `.lovable/`)
- Backend: Cloudflare Worker → Appwrite Functions (node-22)
- Auth: Appwrite JWT (localStorage "jwt"), Silent Refresh кожні 10хв
- Візуальні схеми: drakonwidget.js (embed), компіляція: drakontechgen.js
- Лінкер: solution.json → збірка bundle.js/bundle.lua

### ПРАВИЛО СИНХРОНІЗАЦІЇ
Після кожної зміни в `src/` — скопіюй файл у `.lovable/src/` і закоміть обидва.

### БЛОК 1: UX ПОКРАЩЕННЯ ВАЛІДАЦІЇ (DRK-9)

Зараз реалізовано:
- Помилки показуються як маленькі бейджі під тулбаром
- При спробі зберегти з помилками — toast "Діаграма містить помилки структури"
- Збереження блокується

ПОТРІБНО:
1. **Покращити видимість помилок**: при блокуванні коміту розгорнути панель помилок з повним списком issues та описом кожної (зараз — тільки бейджі з nodeId, деталі видно тільки в tooltip)
2. **Підсвітка проблемних вузлів**: при кліку на помилку виділити відповідний вузол на холсті (якщо widget API підтримує `selectItem(nodeId)` або `scrollTo(nodeId)`)
3. **Warning vs Error розрізнення**: попередження (warnings) не блокують збереження, але мають показуватись окремо від помилок. Додати лічильник: "2 errors, 3 warnings"
4. **Autofix кнопки**: ir-validator-core.ts вже повертає `autofixes[]` (merge_terminals, remove_orphan). Додати кнопку "Auto-fix" для безпечних виправлень

Файли:
- `src/components/drakon/DrakonEditor.tsx` (рядки 856-885 — панель issues)
- `src/lib/htse/ir-validator-core.ts` (autofixes)

5. **Фільтр за типом**: кнопки-тогли для фільтрації: "Схеми (.drakon)" / "Код (.js/.lua)" / "Документація (.md)"

ПОТРІБНО:

4. **Compilation errors panel**: якщо drakontechgen повертає помилки (onError callback) — показати їх окремою панеллю замість toast

Файли:
- `src/components/files/ProjectFileManager.tsx` (compileDiagramClientSide, рядки 54-172)

### БЛОК 5: ЗАГАЛЬНИЙ UX

1. **Keyboard shortcuts**:
   - `Ctrl+S` — зберегти діаграму (вже є ⌘K для command palette, потрібен save shortcut)
   - `Ctrl+Z`/`Ctrl+Y` — undo/redo (форвардити в widgetRef)
   - `Ctrl+E` — export JSON

2. **Unsaved changes guard**: при навігації з незбережених змін — показати підтвердження (компонент UnsavedChangesGuard.tsx вже є, перевірити що він підключений до DrakonEditor)

3. **Mobile experience**: перевірити що DrakonEditor працює на тач-пристроях — pinch-to-zoom, tap-to-select. MobileNavigationDock вже є.

4. **EVIDENCE панель**: зараз показує "Waiting for Phase C compiler trace data..." — наповнити реальними даними: останні compile results, validation issues, git commit history

5. **Offline mode indicator**: якщо GitHub API недоступний — показати banner "Offline mode: changes saved locally"

## Готові наступні кроки (що запустити першим)

Рекомендую почати з пріоритету 1-3 — це швидкі зміни з великим впливом:

1. Language detection: замінити filePath.includes("lua") на читання solution.json або project-level config
2. Validation panel: розгорнути повний список помилок при блокуванні
3. Ctrl+S shortcut: додати глобальний keyboard handler в DrakonEditor
