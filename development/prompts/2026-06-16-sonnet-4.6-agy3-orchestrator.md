## ПРОТОКОЛ ДЕЛЕГУВАННЯ (критично)

### Крок 1 — записати задачу в `TASKS.md` проєкту

Формат **рівно**: `[ ] TASK-N` (НЕ `## TASK-N:` — старий формат).
Задача має бути **атомарна**: AGY3 таймаутить на розпливчастих складних задачах.
Один чіткий результат, явні файли, явний критерій готовності.

### Крок 2 — запустити через `agy-task.sh`, ЧЕКАЮЧИ завершення

**ПРАВИЛЬНО** (SSH тримає сесію до кінця задачі):
```bash
sshpass -p 'TermuxSsh2026!' ssh -o StrictHostKeyChecking=no -p 8022 u0_a410@192.168.3.204 \
  'bash ~/bin/agy-task.sh "TASK-N" 2>&1 | tee ~/agy-task.log'
```
У Bash-tool: **`run_in_background: true`, `timeout: 600000`**.

**ЗАБОРОНЕНО** — `nohup ... &`:
```bash
# НЕПРАВИЛЬНО — SSH виходить миттєво (exit 0), нотифікація приходить ДО реального завершення:
nohup bash ~/bin/agy-task.sh "TASK-N" > ~/agy-task.log 2>&1 &
```
Причина: при `nohup &` ти отримаєш сигнал «готово» поки AGY3 ще працює → хибна верифікація.

### Крок 3 — НЕ запускати кілька фонових задач одночасно

Кожна `run_in_background` задача = окремий термінал. Паралельні важкі задачі ламають
слабкі хости. Одна задача → верифікація → наступна.

## GitNexus-FIRST (перед плануванням задач)

Перш ніж писати задачу на зміну коду — **сам** звір факти з графа, не покладайся на пам'ять.
GitNexus MCP: `https://gitnexus.exodus.pp.ua/api/mcp` (репо `ai-drakon-scaffolder`).

Якщо маєш нативні MCP-інструменти `mcp__gitnexus__*` — використовуй `query`/`context`/`impact`.
Інакше — curl (MCP вимагає сесії, SSE-формат):
```bash
~/bin/gitnexus.sh query "ComponentName" ai-drakon-scaffolder    # де використовується
~/bin/gitnexus.sh context "src/components/X.tsx" ai-drakon-scaffolder  # контекст файлу
~/bin/gitnexus.sh impact "functionName" ai-drakon-scaffolder    # blast radius
```
**Правило:** якщо `impact` показує >3 залежних — це HIGH risk, познач у задачі для AGY3 і
сам перевір, перш ніж дозволити зміну.
